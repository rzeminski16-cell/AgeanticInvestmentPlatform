Anatomy of a Research Run

Twenty-five steps turn one company name into one institutional-style research report. Six of them stop and wait for you. Here is what happens in between, and who is allowed to do what.

Deterministic Python owns every number and every fact. The language model owns planning, interpretation, comparison, adversarial challenge and writing.

The rule everything else follows from

Reading the diagram

Three kinds of work, kept apart on purpose

The colours below run through every diagram on this page. The typography carries the same distinction: anything set in monospace is a name the code knows — a step, a role, a stored value. Anything in serif is prose a person or a model wrote.

Deterministic

Fetching, hashing, parsing, all arithmetic, unit conversion, point-in-time filtering, citation verification. Tested, repeatable, and the only thing allowed to produce a number.

Model call

Planning, judging relevance, proposing an assumption with reasons, writing prose from evidence code assembled, and attacking the finished thesis. Never arithmetic.

Your decision

A full stop. The run pauses and spends nothing further until you answer. What you were shown is hashed, so approving one thing and running another is refused.

Part two — the agents

Eight roles, each with one job and a leash

An agent here is a narrow thing: one role, one output contract, one list of tools it may ask for. All of that is data in a registry, not something a class can declare about itself — so the only way to widen what an agent may do is to change the registry, in a commit, with an architecture decision record attached.

planner

Opus · highno toolsADR 0035

Which sections, which sources, which risks — decided before anything is fetched.

What stops it inventingIt holds no tools and may not state a finding. Its plan is prose about intent, and a person approves it before any money moves.

analysis

Sonnet · medium4 toolsADR 0036

Five workers, one topic each: the company, its industry, the macro backdrop, recent events, technical context.

What stops it inventingIt never calls a tool. It requests one in a schema and code decides whether that request is permitted, then executes it. Findings must name evidence; a figure of its own is not a valid output.

peer_proposal

Sonnet · mediumno toolsADR 0059

Comparable companies, each named by ticker with a reason for being on the list.

What stops it inventingA ticker is a claim about the world, so code checks it: every one is resolved against EDGAR's registry, and a name that does not resolve is refused before a single request goes out.

assumption_proposal

Opus · highno toolsADR 0046

Exactly two numbers no filing answers: the perpetual growth rate, and the exit multiple.

What stops it inventingIts schema has two fields and no others, so it cannot volunteer a third. Values outside code-set bounds are dropped rather than clamped — a silently corrected assumption is worse than a missing one.

report_writer

Opus · highno toolsADR 0042

One built-in section at a time, written from the structured evidence pack code assembled for it.

What stops it inventingNo tools, so it writes only from what it was handed. Every numeral in the prose must resolve to a stored fact or a recorded calculation, or the draft does not stand.

custom_section

Sonnet · medium3 toolsADR 0037

A section you wrote the instructions for, drafted under the policy those instructions compose into.

What stops it inventingYour instructions are additive only — enforced structurally, not by asking nicely. No wording in a skill file can switch citations off, set a rating, or step around the point-in-time rules.

validator

Sonnet · mediumno toolsADR 0038

Help where the deterministic verifier could not settle something — usually locating a candidate excerpt for a claim.

What stops it inventingIt is advisory by construction: no verdict field is writable from its output. It can point at a passage; only code decides whether the passage says what the claim says.

red_team

Opus · highno toolsADR 0039

Attack the thesis. Scored, evidence-cited challenges to what the report concluded.

What stops it inventingIt runs in a separate context and is shown the claims and the evidence index only. Every challenge must cite, so it cannot object by assertion any more than the draft could assert by assertion.

Part three — provenance

How a filing becomes a sentence you can trust

This is the chain the whole platform exists to protect, and every link in it is code. The model may propose a citation; only code may confirm one, by re-reading the stored document by its hash and checking the quoted words are really in it.

Two properties fall out of the shape. Point-in-time is enforced at acquisition, not at reading — a document published after your as-of date never enters the run, so no later code path can use it by forgetting to check. And units travel with the arithmetic: a mismatch raises rather than coercing, which is what stops a whole-company figure being divided by a per-share one. That error is wrong by the entire share count and looks completely ordinary on the page.

Part five

What it refuses to do

Worth stating plainly, because the refusals are the design.

  • ✕Print a figure it cannot trace to a filing or to a formula.
  • ✕Compare against peers nobody agreed to.
  • ✕Run a discounted cash flow on a bank — the sector model blocks it rather than footnoting it.
  • ✕Publish a report whose citations do not verify against the archived bytes.
  • ✕Treat a fetched page as an instruction. Untrusted content is wrapped and labelled as data, and tool permission is enforced in code — so text in a document cannot cause a call the agent's role does not already allow.
  • ✕Spend past its ceiling because one step looked cheap.
