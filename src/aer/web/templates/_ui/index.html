{# One import per page. `{% import "_ui/index.html" as ui with context %}` and then `ui.sheet(...)`, so a page names the component rather than the classes that make it. The rule for everything here: **a macro takes data and never classes.** A component that accepted a class string would let a caller build a sheet that is not a sheet, and the reason to have components at all is that there is one answer to what a sheet looks like. Variants are a closed set mapped to complete, literal class names — `tests/test_components.py` fails a macro that grows a `class` or `style` argument, and `tests/test_palette_migration.py` fails a class assembled from parts, which Tailwind's scanner cannot see and renders with no colour at all. **The `set` beside each import is load-bearing.** Jinja does not re-export a name brought in with `{% from %}`, so a file that only imported them exported nothing and `ui.sheet` raised `UndefinedError` — which nothing noticed, because this file shipped before any page used it.
