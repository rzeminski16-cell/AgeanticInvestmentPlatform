Rendering it twice would put two `id="aer-badge-approvals"` nodes on every page, and an out-of-band swap targets an id — the first would fill and the second would show nothing for ever. That constraint is why the responsive answer is CSS rather than markup. **It ships `open`, and script closes it when the window is narrow** (decision B7). The direction matters. Shipping it closed would need author CSS to reveal a *closed* `
`, which is not reliably specified across engines — Chromium's `::details-content` now carries `content-visibility: hidden`, which a `display` override on the child does not defeat (D7). Shipping it open needs no reveal at all: at wide widths it is already open and the summary is simply removed from the flow. With no script it stays open at every width, which at 320px is a panel above the content with every link reachable. That is the safe way to fail and it is now a decision rather than an accident. **The rail is a fixed-dark region** (ADR 0088). `data-scheme="dark"` gives it the dark scheme's accents in both themes, so a focus ring inside it resolves to `#b5ecf0` at 11.43:1 rather than the light `#00606d` at 2.04:1 — a WCAG 2.2 SC 1.4.11 failure that nothing measured, because the rail's colours were in no token table. **Selection is never carried by the fill.** `#183945` on the rail is 1.21:1, which is nothing. The teal leading rule at 11.43:1 carries it visually and `aria-current="page"` carries it to everybody else; the fill is decorative and is written down as decorative so a later simplification cannot quietly make it the only cue. #}
