{# The one drawer, in the shell, so no page has a second implementation of a focus trap. It is empty and `hidden` until htmx swaps something into `#aer-drawer-body`; opening is `static/js/drawer.js`'s and nothing here knows how it happens. A page opts in by pointing a link's `hx-target` at that id — see the comment at the top of that file for the whole contract, which is four attributes. **The semantics are markup, not JavaScript.** `role`, `aria-modal` and `aria-labelledby` are here rather than set on open, so the panel is a dialogue in the DOM a reader inspects and not only in the one a script got round to editing. What a server cannot send is the behaviour — focus, Escape, the scroll lock — and that is exactly what the script owns. `hidden` rather than a class: it is the attribute assistive technology already understands, so a stylesheet that failed to load leaves the drawer closed rather than covering the page. #}
{# Not focusable and not a button. The overlay is a convenience for a mouse; every reader without one has Escape and the close button, both of which are real controls. #}
